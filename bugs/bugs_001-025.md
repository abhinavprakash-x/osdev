# Bugs 001–025

## BUG-001 — `.bss` is not zero-initialized

**State:** FIXED  
**Severity:** Critical  
**Component:** Boot / Linker

`kernel_entry.asm` previously jumped directly to `kmain`, while the flat binary linker configuration did not emit `.bss` contents. Globals such as `tick_count`, keyboard state, and buffers could start with garbage values.

**Original fix noted:** 2026-09-18.

---

## BUG-002 — User tasks start with an unmapped address space

**State:** OPEN  
**Severity:** Critical  
**Component:** Tasks / Address Space

`create_user_task` creates a page directory but maps neither the user code nor user stack. Unless the caller maps them first, the task immediately page-faults. The API contract is unsafe and incomplete.

---

## BUG-003 — User-test allocation failures leak resources

**State:** OPEN  
**Severity:** Critical  
**Component:** User Task Creation

`launch_user_test` previously freed only the code page when stack allocation failed. The task PCB, kernel stack, and page directory remained allocated.

---

## BUG-004 — User-test mapping failures are ignored

**State:** OPEN  
**Severity:** Critical  
**Component:** User Task Creation

`launch_user_test` ignores both `paging_map_page()` return values, potentially scheduling a task with unmapped code or stack.

---

## BUG-005 — Scheduler hangs when every task is waiting

**State:** OPEN  
**Severity:** Critical  
**Component:** Scheduler

`schedule` loops indefinitely if no task is runnable. When invoked with interrupts disabled, timer ticks cannot advance, so sleeping tasks never wake.

---

## BUG-006 — Null task insertion causes a kernel crash

**State:** FIXED  
**Severity:** Critical  
**Component:** Scheduler / Tasks

`task_add` previously did not validate `new_task`. An allocation failure passed from `kmain` could be dereferenced.

**Original fix noted:** 2026-09-19.

---

## BUG-007 — PMM can write beyond its bitmap from E820 entries

**State:** FIXED  
**Severity:** Critical  
**Component:** PMM / E820

`pmm_init` previously converted 64-bit E820 ranges directly to bitmap indexes without clipping them to the 4-GB bitmap limit. High-memory or overflowing entries could call `clear_bit()` out of bounds.

**Original fix noted:** 2026-09-18.

---

## BUG-008 — Reserved physical frames can be released and reallocated

**State:** OPEN  
**Severity:** Critical  
**Component:** PMM

`pmm_free_block` checks whether a bit is set, but does not check whether the frame belongs to a usable E820 region. Passing a reserved address above 1 MiB can make hardware/kernel memory available for reuse.

---

## BUG-009 — Kernel image size is not checked against the bootloader read limit

**State:** OPEN  
**Severity:** High  
**Component:** Bootloader / Build

The bootloader reads a fixed number of sectors while the image builder appends a fixed amount of padding. A kernel larger than the bootloader read limit can be silently truncated.

---

## BUG-010 — User-code copy can overflow one physical page

**State:** OPEN  
**Severity:** Critical  
**Component:** User Task Creation

`launch_user_test` allocates one physical page and copies `user_code_size` bytes without checking that the code fits in 4096 bytes.

---

## BUG-011 — Keyboard ring buffer overwrites unread input

**State:** OPEN  
**Severity:** High  
**Component:** Keyboard Driver

`keyboard_handler` advances the producer index without checking whether the circular buffer is full, losing keystrokes and corrupting queue ordering.

---

## BUG-012 — Physical-memory accounting is inconsistent with the E820 map

**State:** OPEN  
**Severity:** High  
**Component:** PMM

`pmm_init` counts usable frames in `total_blocks`, then independently adds 256 reserved frames to `used_blocks`, even when those frames were not usable. `meminfo` can therefore report incorrect or negative free memory.

---

## BUG-013 — Shell arbitrary memory access can crash or corrupt the kernel

**State:** OPEN  
**Severity:** High  
**Component:** Shell

`peek` / `poke` handling dereferences arbitrary user-provided addresses without checking mapping, alignment, or permissions. Invalid input can cause a kernel page fault or memory corruption.

---

## BUG-014 — Dead-task cleanup can use freed memory

**State:** OPEN  
**Severity:** Critical  
**Component:** Scheduler

`schedule` can eventually unlink and free `current_task`, then continue using it as `prev_iterator` when multiple dead tasks remain.

---

## BUG-015 — `scheduler_init()` dereferences failed allocation

**State:** FIXED  
**Severity:** Critical  
**Component:** Scheduler

`scheduler_init` previously did not check whether `kmalloc()` returned `NULL` before dereferencing the initial task.

**Original fix noted:** 2026-09-19.

---

## BUG-016 — Existing user address spaces miss later kernel mappings

**State:** OPEN  
**Severity:** Critical  
**Component:** Paging

`paging_create_address_space` copies kernel PDEs only once. Later heap growth or other kernel mappings can be absent from older address spaces, causing faults while kernel code runs under those page directories.

---

## BUG-017 — Physical user frames are accessed as virtual addresses

**State:** OPEN  
**Severity:** Critical  
**Component:** User Task Creation / Paging

`launch_user_test` passes a physical address directly to `memcpy()`. This only works while the frame is identity-mapped.

---

## BUG-018 — Heap allocation arithmetic can overflow

**State:** OPEN  
**Severity:** Critical  
**Component:** Heap

`kmalloc` can wrap during alignment and page-count calculations. Requests such as `alloc -1` can produce invalid sizes, recursive allocation, or heap exhaustion.

---

## BUG-019 — Shell `alloc` passes unchecked `atoi()` results into `kmalloc`

**State:** OPEN  
**Severity:** Critical  
**Component:** Shell / Heap

The `alloc` command passes unchecked signed `atoi()` results into `kmalloc()`. Negative or otherwise invalid user input can therefore reach the heap allocator as an unsigned size.

---

## BUG-020 — `paging_map_page()` overwrites existing mappings and leaks the old frame

**State:** OPEN  
**Severity:** Significant  
**Component:** Paging / PMM

`map_page` assigns a new PTE without checking whether one was already present. Replacing a mapping can lose the old physical-frame reference while PMM still considers the frame allocated.

---

## BUG-021 — Page-table aliases are not invalidated after reclamation

**State:** OPEN  
**Severity:** Significant  
**Component:** Paging

`unmap_page` invalidates only the unmapped virtual page, not the recursive page-table alias after the page table itself is reclaimed.

---

## BUG-022 — Paging APIs do not enforce page alignment

**State:** OPEN  
**Severity:** Significant  
**Component:** Paging

`map_page` accepts unaligned virtual and physical addresses.

---

## BUG-023 — Paging APIs do not validate physical-frame ownership or validity

**State:** OPEN  
**Severity:** Significant  
**Component:** Paging / PMM

`paging_map_page` accepts arbitrary physical addresses, including reserved or unallocated frames.

---

## BUG-024 — Address-space destruction assumes every user mapping owns its frame

**State:** OPEN  
**Severity:** Significant  
**Component:** Paging / PMM

`paging_destroy_address_space` frees every mapped physical page, which breaks if frames are shared or aliased.

---

## BUG-025 — E820 ranges are rounded incorrectly

**State:** FIXED  
**Severity:** Significant  
**Component:** PMM / E820

`pmm_init` previously floored both start and length. Partial pages could be incorrectly treated as usable.

**Original fix noted:** 2026-09-18.
